# 《纸牌建筑师》玩法完善与长期开发方案

> 文档状态：规划稿  
> 项目定位：轻量但具有真实物理反馈的纸牌工程挑战游戏  
> 核心目标：把当前物理搭建原型发展为有目标、有反馈、愿意反复挑战的完整游戏

## 1. 当前基础

游戏目前已经具备以下核心能力：

- Bridge 和 Poker 两种牌型尺寸。
- 多种平放、直立和倾斜放置预设。
- 快捷放置、精确放置、移动和删除工具。
- 高度锁定、物理冻结、存档和读档。
- 风力测试、落物冲击和基础稳定性测试。
- 挑战模式与自由搭建模式。
- 纸牌数量、高度和关卡目标显示。
- 原版蓝、暖白和深色三套视觉主题。

现阶段的主要问题不是缺少搭建工具，而是搭建行为与游戏目标之间的联系还不够紧密。玩家能够搭建纸牌屋，但缺少持续驱动其观察、试验、失败、改进和再次挑战的完整循环。

## 2. 核心定位

建议将游戏明确定位为：

**轻量但真实的纸牌工程挑战游戏。**

游戏的核心乐趣应来自：

- 使用有限数量的纸牌解决结构问题。
- 在测试开始前产生紧张和不确定感。
- 观察建筑摇晃、变形以及最终保持稳定或倒塌。
- 找出倒塌原因并改进设计。
- 使用更少纸牌、更稳定结构获得更高评价。
- 逐步掌握支撑宽度、重心、摩擦、跨度和对称性。

不建议将游戏发展为单纯的 3D 摆放工具，也不建议在核心循环完成前优先添加大量装饰、剧情或收集内容。

## 3. 核心游戏循环

完整的单局流程建议设计为：

1. 玩家阅读结构目标和限制条件。
2. 观察建造区域、测试方向和可用牌数。
3. 选择合适的放置预设并搭建结构。
4. 在测试前检查高度、重心和接触关系。
5. 启动风力、稳定性或冲击测试。
6. 观察建筑在测试中的摇晃、位移和倒塌过程。
7. 查看评分和失败原因分析。
8. 返回搭建阶段修改结构。
9. 使用更少纸牌或更稳定的结构获得更高评价。

核心循环可以概括为：

> 观察目标 → 设计结构 → 搭建 → 测试 → 分析 → 改进 → 再次挑战

## 4. 关卡体系

建议使用五个章节逐步引入工程概念，而不是一开始同时开放所有机制。

### 4.1 第一章：学会站立

目标是让玩家掌握最基础的接地、倾斜和支撑方法。

建议关卡：

1. 使用 2 张牌搭建能够独立站立的 A 字结构。
2. 使用 4 张牌搭建两个相连的 A 字结构。
3. 使用 6 张牌搭建带横梁的基础结构。
4. 使用不超过 10 张牌搭建一层有屋顶的房子。

教学重点：

- 长边和短边接地的区别。
- 左倾、右倾、前倾和后倾预设。
- 高度锁定。
- 摩擦力和接触面积。
- 为什么两张牌互相支撑比单张牌直立更稳定。

### 4.2 第二章：结构稳定

目标是让玩家理解支撑范围、重心和对称性。

建议关卡：

1. 在指定建造区域内完成结构。
2. 建筑达到规定高度并维持数秒。
3. 在顶部形成可承载物体的平台。
4. 使用限定数量的纸牌完成指定高度。
5. 搭建左右对称的支撑结构。

教学重点：

- 底部支撑宽度。
- 重心位置。
- 左右重量平衡。
- 横梁跨度。
- 多组支撑之间的距离。

### 4.3 第三章：环境测试

目标是让玩家学习针对方向性外力进行加固。

建议关卡：

1. 承受单方向持续轻风。
2. 承受左右交替阵风。
3. 承受逐渐增强的风力。
4. 在轻微倾斜的地面上保持稳定。
5. 连续承受两个方向的风力。

设计要求：

- 风力方向必须清晰显示。
- 测试参数尽量固定，避免纯随机失败。
- 阵风可以变化，但相同关卡应使用固定随机种子。
- 高层建筑风力测试应比一层建筑更困难。

### 4.4 第四章：冲击测试

目标是让玩家处理瞬时冲击和局部破坏。

建议关卡：

1. 小球从较低位置落下。
2. 重物砸向屋顶中心。
3. 重物落入预先显示的目标区域。
4. 连续落下多个轻型物体。
5. 承受冲击后继续完成风力测试。

教学重点：

- 屋顶支撑点。
- 冲击力传递。
- 局部加固。
- 冗余支撑。
- 单点失效和连锁倒塌。

### 4.5 第五章：工程挑战

目标是检验玩家对前面机制的综合掌握。

建议关卡：

1. 在规定高度下使用最少纸牌。
2. 在规定牌数下追求最高高度。
3. 只允许使用指定放置预设。
4. 禁止冻结物理完成建筑。
5. 在倒计时结束前完成搭建。
6. 修复一座已经损坏的纸牌屋。
7. 在风力和落物组合测试中存活。

## 5. 测试过程表现

测试过程需要成为每一局最紧张、最值得观看的部分。

### 5.1 测试前

- 显示测试类型、方向和强度。
- 给玩家一次保存检查点的机会。
- 使用 3 秒倒计时。
- 镜头自动稍微拉远，让完整建筑进入视野。
- 暂时弱化非关键 UI。

### 5.2 测试中

- 风力使用清晰但不过度遮挡的方向线。
- 显示实时测试强度和剩余时间。
- 建筑发生明显位移时给出轻量反馈。
- 关键支撑开始失稳时可以轻微降低时间速度。
- 不要在刚出现晃动时立即判定失败。

### 5.3 测试后

- 成功后继续运行短时间物理，让玩家确认结构真正保持稳定。
- 倒塌时进入短暂慢动作。
- 失败后保留倒塌现场，允许自由观察。
- 支持回放最后数秒。
- 标记第一张明显失稳的纸牌。

## 6. 倒塌分析系统

倒塌分析可以成为游戏区别于普通搭建沙盒的核心特色。

建议记录以下数据：

- 第一张发生明显位移的纸牌。
- 第一个失去接触的支撑点。
- 最大水平位移。
- 最大倾斜角度。
- 测试前后的结构高度变化。
- 倒塌方向。
- 测试结束后仍保持稳定的纸牌数量。

可以根据数据生成简单的失败原因：

- 底部支撑过窄。
- 左右重量不平衡。
- 屋顶跨度过大。
- 接触面积不足。
- 重心过高。
- 支撑之间距离过大。
- 冲击位置缺少直接支撑。
- 单张纸牌失效引起连锁倒塌。

分析界面不需要使用复杂工程术语，应提供玩家能够立即用于下一次修改的建议。

## 7. 评分系统

不应只使用高度作为成功标准，否则容易鼓励细长但不稳定的结构。

建议总分由以下部分组成：

| 评分项目 | 评价内容 |
| --- | --- |
| 稳定性 | 测试后的剩余高度、倾斜程度和整体位移 |
| 效率 | 使用纸牌数量和剩余纸牌数量 |
| 完整度 | 测试结束后仍保持原位的纸牌比例 |
| 精度 | 是否位于指定区域、是否达到高度和结构要求 |
| 耐久度 | 经受风力、冲击或组合测试的强度 |

建议星级：

- 一星：完成基本目标。
- 二星：结构完整度或稳定性达到进阶要求。
- 三星：节省纸牌、超过目标高度或几乎没有位移。
- 完美标记：测试结束后没有任何纸牌倒下。

同一关卡应允许玩家反复提高成绩，而不是通关后立即失去价值。

## 8. 蓝图和长期成长

### 8.1 蓝图系统

完成教学或特殊挑战后解锁蓝图：

- A 字架。
- 双 A 支撑。
- 横梁结构。
- 一层房屋。
- 双层房屋。
- 塔楼。
- 平台。
- 拱门。

蓝图只提供半透明参考线和关键接触点，不应自动完成搭建。

### 8.2 建筑档案

玩家可以保存：

- 建筑名称。
- 使用牌数。
- 最大高度。
- 通过的最高风力等级。
- 冲击测试成绩。
- 完整度和稳定性评分。
- 建筑截图。
- 使用的牌型和预设。

### 8.3 成就系统

示例：

- 使用 2 张牌首次完成独立站立。
- 不锁定物理完成一层房屋。
- 使用 8 张或更少纸牌完成屋顶结构。
- 承受最高等级风力。
- 完成一次无倒塌测试。
- 建筑累计倒塌 50 次。
- 移除一张牌引发完整连锁倒塌。

## 9. 可重复游玩的模式

### 9.1 生存模式

每轮测试通过后：

1. 风力或落物强度提高。
2. 玩家获得少量新纸牌。
3. 玩家在原建筑基础上继续加固。
4. 进入下一轮更强测试。

核心循环：

> 搭建 → 测试 → 获得纸牌 → 加固 → 更强测试

该模式适合作为完成教学后的主要长期玩法。

### 9.2 每日挑战

每天固定以下条件：

- 可用牌数。
- 牌型尺寸。
- 建造区域。
- 风向和强度。
- 落物参数。
- 测试随机种子。

所有玩家使用相同条件，便于比较成绩。

### 9.3 修复模式

游戏预先生成一座部分损坏或结构不合理的建筑，玩家只能增加有限数量的牌进行修复。

### 9.4 拆除模式

玩家需要选择移除一张或数张牌，使指定区域倒塌，同时保护其他区域。

### 9.5 自由实验室

自由搭建模式增加：

- 风力方向和强度控制。
- 落物重量和高度控制。
- 地面倾角控制。
- 时间速度控制。
- 实时稳定性数据。

## 10. 搭建体验完善

建议逐步补充：

- 完整的撤销和重做历史。
- 临时隐藏全部 UI。
- 正视、侧视、俯视和透视镜头快捷键。
- 自动聚焦当前建筑。
- 网格吸附开关。
- 当前旋转角度显示。
- 当前卡牌高度显示。
- 放置前显示关键接触点。
- 幽灵牌发生穿插时变红。
- 快速复制上一张牌的角度。
- 蓝图参考线。
- 测试前自动保存检查点。
- 放置失败或超过牌数时给出明确反馈。
- 允许调节旋转步进，例如 1°、5° 和 10°。

## 11. 技术与公平性要求

### 11.1 可重复测试

- 每个正式关卡使用固定测试参数。
- 随机风力和落物位置使用可保存的随机种子。
- 重试关卡时必须得到相同测试条件。

### 11.2 物理稳定性

- 明确物理时间步长。
- 避免帧率变化影响关卡结果。
- 对极小穿透和初始碰撞进行修正。
- 测试开始前等待结构进入稳定状态。
- 评分使用物理数据而不是纯视觉判断。

### 11.3 性能

- 保持纸牌几何体和纹理缓存。
- 关闭不必要的阴影接收。
- 环境光使用本地离线资源。
- 风力可视化使用实例化渲染。
- 大量纸牌模式下动态降低阴影分辨率。

## 12. 开发阶段

### 12.1 第一阶段：完成核心游戏循环

目标：让现有关卡真正具备挑战性和重玩价值。

优先开发：

1. 重新制作 8～10 个渐进式关卡。
2. 建立稳定性、效率、完整度评分。
3. 增加测试倒计时和倒塌慢动作。
4. 增加基础失败原因提示。
5. 增加完整撤销、重做。
6. 增加正视、侧视和俯视镜头。

验收标准：

- 新玩家无需阅读外部说明即可完成前三关。
- 每个关卡至少存在两种可行结构。
- 玩家失败后能够理解主要失败原因。
- 玩家愿意为了更高星级重复挑战。

### 12.2 第二阶段：增加重复游玩价值

优先开发：

1. 生存模式。
2. 更多风力和冲击测试。
3. 蓝图解锁系统。
4. 建筑档案。
5. 成就系统。
6. 更详细的结构数据与回放。

### 12.3 第三阶段：形成长期内容

优先开发：

1. 每日挑战。
2. 固定随机种子和成绩校验。
3. 建筑方案导出和导入。
4. 分享建筑截图与成绩。
5. 排行榜。
6. 社区挑战关卡。

## 13. 下一版本推荐范围

下一版本不建议同时实现所有规划。推荐聚焦以下内容：

### 必须完成

- 8～10 个渐进关卡。
- 新评分系统。
- 测试倒计时。
- 倒塌慢动作。
- 基础失败原因分析。
- 撤销和重做。
- 三个固定镜头快捷键。

### 暂缓

- 排行榜。
- 复杂社交功能。
- 大量卡牌皮肤。
- 剧情系统。
- 付费成长系统。
- 自动生成大量随机关卡。

## 14. 成功标准

当玩家完成一次挑战后，应自然产生以下想法之一：

- “再调整一下支撑位置应该就能成功。”
- “我可以少用两张牌。”
- “换一种屋顶结构可能更稳定。”
- “刚才到底是哪张牌先倒的？”
- “我想看看它能承受多大的风。”

如果游戏能够持续触发这些想法，就说明核心工程挑战循环已经成立。
