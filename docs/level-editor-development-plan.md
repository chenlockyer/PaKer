# 关卡编辑器开发方案

## 定位

官方关卡与玩家关卡共用同一套数据格式和编辑器。区别仅在来源、发布权限和分发位置，不维护两套运行逻辑。

## 当前 MVP

- 从个人蓝图或官方教学蓝图创建关卡。
- 编辑名称、说明、作者、标签和来源类型。
- 编辑最少/最多牌数、目标高度和测试时间。
- 支持稳定性、风力、落物冲击三种测试。
- 保存时深拷贝完整蓝图到关卡，不依赖个人蓝图库。
- 记录来源蓝图 ID，仅用于追溯。
- 使用校验值检测内嵌蓝图损坏或篡改。
- 本地关卡库、导入、导出、删除和一键试玩。
- 试玩时复用正式挑战物理与结算流程，并启动内嵌蓝图引导。
- 编辑已有草稿，主动替换内嵌蓝图，复制关卡进行改造。
- 将稳定性、风力和落物测试编排为连续的多阶段测试。
- 任何编辑都会撤销旧试玩认证，只有实际通关且校验通过才能发布。

## 数据原则

草稿和发布文件都必须自包含。任何关卡运行时只能读取 `embeddedBlueprint`，不得通过 `sourceBlueprintId` 回查个人蓝图库。

更新源蓝图不会静默改变已有的关卡。后续加入“替换关卡蓝图”操作时，必须重新生成校验值并要求重新试玩。

## 下一阶段

- 自定义成功条件和星级评分。
- 初始场景物件与限制区域。
- 官方关卡写入项目资源目录的开发者发布流程。
- 关卡包预览图、版本迁移、作者谱系和分享码。
