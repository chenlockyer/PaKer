# 《纸牌建筑师》蓝图系统开发方案

> 文档状态：产品与技术开发规划  
> 功能定位：连接官方教学、玩家创作、结构分享、社区挑战与对战建筑的核心内容系统  
> 适用项目：PaKer /《纸牌建筑师》  
> 当前技术基础：React、Three.js、React Three Fiber、Cannon、Electron  
> 核心原则：蓝图用于指导和传播结构知识，不提供一键自动建造

## 当前实施状态（2026-07-29）

- P0：已完成。蓝图使用独立版本化格式保存卡牌实时物理位置与四元数姿态，支持本地存储和安全导入导出。
- P1：已完成。支持从蓝图库启动投影、地面选择原点、整体旋转、显示/隐藏、重新定位和完整结构幽灵牌。
- P2：已完成。支持步骤高亮、自动推进、位置/高度/姿态/接地边判定、正确/接近/错误反馈、稳定时间及步骤恢复。蓝图不干预物理锁定，卡牌统一服从场景“物理”开关。
- P4：已完成。内置 A 字架、双 A 字支撑、横梁和一层纸牌屋四个官方课程，支持三档辅助、顺序解锁与本地完成记录。
- P3：已完成。支持搭建录制、步骤时间线、卡牌分组、步骤说明、推荐预设、容差编辑、镜头提示、从头测试、草稿和发布。

后续从 P5 玩家分享继续。

## 1. 功能愿景

蓝图系统不应被实现成只能服务新手教学的临时功能，而应该成为游戏长期内容生态的基础设施。

蓝图需要同时支持：

1. 官方制作分步骤教学关卡。
2. 玩家保存自己的建筑作品。
3. 玩家录制并分享搭建过程。
4. 其他玩家投影蓝图并照图搭建。
5. 玩家基于蓝图发起限时、限牌和稳定性挑战。
6. 保存炮台、弩、飞镖塔和投手等对战建筑。
7. 对玩家蓝图进行改造，并保留原作者和创作谱系。
8. 后期接入好友分享、Steam 创意工坊和游戏内社区。

核心内容循环：

> 官方蓝图教学 → 玩家掌握结构 → 玩家自由创作 → 保存蓝图 → 分享与改造 → 发起挑战 → 形成社区结构流派

## 2. 设计原则

### 2.1 蓝图不是自动建造

蓝图只提供：

- 目标轮廓；
- 搭建顺序；
- 推荐预设；
- 接地边和接触点；
- 操作提示；
- 位置和角度纠错。

玩家仍然需要亲自：

- 选择姿态；
- 移动卡牌；
- 调整角度；
- 锁定高度；
- 完成接触；
- 释放物理；
- 处理倒塌。

### 2.2 从模仿逐步过渡到独立建造

同一份蓝图应支持三档辅助：

1. **完整引导**：逐张显示、推荐预设、强吸附、操作说明。
2. **结构提示**：显示整体轮廓和关键支撑，弱吸附，不主动给答案。
3. **轮廓挑战**：只显示最终外形和约束，允许玩家使用自己的方案。

### 2.3 结构意图比坐标更重要

蓝图不能只保存卡牌坐标，还应记录：

- 推荐接地边；
- 所属步骤；
- 支撑作用；
- 接触关系；
- 是否可选；
- 判定容差；
- 何时释放物理；
- 需要通过的测试。

### 2.4 所有蓝图必须版本化

蓝图需要记录：

- 文件格式版本；
- 游戏版本；
- 物理参数版本；
- 卡牌规格版本；
- 最后验证版本。

这样修改摩擦力、碰撞体或卡牌尺寸后，旧蓝图仍可识别和迁移。

## 3. 蓝图类型

### 3.1 官方教学蓝图

由开发者制作，包含完整教学信息：

- 固定或推荐的搭建顺序；
- 步骤说明；
- 结构原理；
- 操作提示；
- 镜头提示；
- 分组物理释放；
- 失败恢复；
- 完成条件。

### 3.2 玩家结构蓝图

保存玩家建筑的最终状态：

- 相对位置；
- 旋转；
- 卡牌尺寸；
- 使用牌数；
- 建筑边界；
- 预览图；
- 作者和标签；
- 稳定性认证。

### 3.3 录制蓝图

除最终结构外，还保存：

- 放置顺序；
- 每步使用的预设；
- 步骤分组；
- 每步确认时的最终姿态；
- 物理释放点；
- 作者说明。

适合复杂建筑、攻略和教学内容。

### 3.4 挑战蓝图

蓝图携带挑战规则：

- 限时；
- 限牌；
- 目标高度；
- 允许区域；
- 禁用工具；
- 风力测试；
- 坠物测试；
- 记忆搭建；
- 最少修正次数；
- 必须或禁止使用的结构。

### 3.5 对战建筑蓝图

用于保存：

- 防御建筑；
- 核心牌位置；
- 发射坡道；
- 直线轨道；
- 发射塔；
- 储弹区域；
- 建筑牌和弹药牌分配。

排位模式中不能直接一键生成，只能作为投影、训练内容或受规则限制的建造参考。

## 4. 用户流程

### 4.1 保存当前建筑

```text
完成建筑
  → 点击“保存为蓝图”
  → 选择蓝图原点和正面方向
  → 自动转换为相对坐标
  → 填写名称、说明、分类和标签
  → 调整预览镜头
  → 运行稳定性测试
  → 保存到“我的蓝图”
```

### 4.2 录制搭建过程

```text
进入蓝图创作模式
  → 开始录制
  → 放置若干张牌
  → 完成当前步骤
  → 填写步骤说明
  → 继续搭建下一组
  → 设置物理释放点
  → 结束录制
  → 编辑步骤时间线
  → 从空场景测试
  → 发布蓝图
```

### 4.3 使用蓝图

```text
打开蓝图库
  → 选择蓝图
  → 阅读尺寸、牌数和难度
  → 在地面选择投影原点
  → 调整整体朝向或镜像
  → 选择辅助等级
  → 按步骤搭建
  → 完成结构测试
  → 收藏、评分或发起挑战
```

### 4.4 分享和改造

```text
打开蓝图详情
  → 导出文件 / 复制分享码 / 发送好友
  → 接收者导入并验证
  → 选择“基于此蓝图改造”
  → 保存新版本
  → 自动记录原作者与来源
```

## 5. 蓝图创作模式

主菜单增加：

- 蓝图创作；
- 蓝图库。

自由建造界面增加：

- 保存为蓝图；
- 开始录制。

### 5.1 创作工具栏

创作模式需要提供：

- 开始、暂停和结束录制；
- 新建步骤；
- 完成当前步骤；
- 将卡牌移动到其他步骤；
- 合并步骤；
- 拆分步骤；
- 调整步骤顺序；
- 编辑目标卡牌；
- 设置推荐预设；
- 标记接地边；
- 标记关键接触点；
- 设置判定容差；
- 设置镜头提示；
- 设置物理释放；
- 保存草稿；
- 从头测试；
- 发布或导出。

### 5.2 时间线

底部显示步骤时间线：

```text
[01 左侧支撑] → [02 右侧支撑] → [03 第二组支撑] → [04 屋顶] → [05 稳定测试]
```

点击步骤后：

- 只高亮本步骤卡牌；
- 其他步骤降低透明度；
- 可以修改标题和说明；
- 可以重新指定卡牌；
- 可以设置本步骤完成条件。

### 5.3 快照创作

玩家不录制过程时，可以直接将当前建筑保存为蓝图。

系统自动：

1. 计算结构包围盒。
2. 找到最低点。
3. 让蓝图最低点落在局部地面。
4. 以结构中心或玩家指定点作为原点。
5. 将所有世界坐标转换为局部坐标。
6. 按历史放置顺序生成默认步骤。
7. 打开步骤编辑器供作者整理。

## 6. 教学运行器

教学运行器负责把蓝图转化为可游玩的教学关卡。

### 6.1 步骤状态

每个步骤具有：

- 未解锁；
- 当前步骤；
- 接近目标；
- 完成；
- 物理验证中；
- 失败；
- 已跳过。

### 6.2 场景表现

目标牌颜色：

- 灰色：未来步骤；
- 蓝色：当前未完成目标；
- 金色：当前重点目标；
- 绿色：正确完成；
- 红色：位置、角度或接地边错误；
- 紫色：建议使用高度锁定。

每张目标牌可显示：

- 半透明轮廓；
- 米字辅助线；
- 接地边高亮；
- 前后方向箭头；
- 接触点；
- 推荐预设；
- 操作快捷键。

### 6.3 当前步骤提示

底部教学条示例：

```text
步骤 2 / 6：放置右侧支撑
目标：长边接地，向左倾斜 10°
作用：与上一张牌形成互相支撑
```

鼠标附近只显示最必要的信息：

```text
按住 C 选择姿态
Space 锁定高度
```

### 6.4 纠错

判定失败不能只显示“错误”，需要区分：

- 位置过远；
- 高度不正确；
- 倾斜方向相反；
- 接地边错误；
- 角度误差过大；
- 放置顺序错误；
- 没有接触指定牌；
- 结构已经倒塌。

示例：

```text
位置正确，但倾斜方向相反
请向左调整 10°
```

### 6.5 分组释放物理

教学阶段使用结构组：

1. 当前组内的牌暂时冻结。
2. 完成能够自支撑的结构组。
3. 解除该组冻结。
4. 验证稳定时间。
5. 通过后进入下一组。
6. 失败时恢复到本组开始前。

例如A字架的两张牌完成后一起释放，而不是第一张放下后立即倒塌。

## 7. 判定系统

### 7.1 基础判定

每张目标牌至少判定：

- 位置距离；
- 高度误差；
- 四元数角度差；
- 接地边；
- 目标区域；
- 必要接触关系。

### 7.2 推荐容差

完整引导默认值：

| 项目 | 默认容差 |
|---|---:|
| 水平位置 | ±0.18 |
| 高度 | ±0.12 |
| 旋转角度 | ±5° |
| 接触位置 | 指定区域内 |

结构提示可以收紧容差，轮廓挑战不要求逐张匹配。

### 7.3 姿态比较

旋转不能直接比较欧拉角，需要使用四元数角度差，避免：

- `180°`和`-180°`被误判；
- 不同欧拉角表示相同姿态；
- 旋转顺序导致误差。

### 7.4 卡牌匹配

简单教学使用“一张目标牌对应一张玩家牌”。

自由轮廓模式需要使用匹配算法：

1. 根据目标区域筛选附近玩家牌。
2. 计算位置、角度和接地边综合误差。
3. 为目标牌分配最合适且未被占用的玩家牌。
4. 允许可选牌和替代结构。

## 8. 数据结构

建议新增：

```ts
type BlueprintCategory =
  | 'tutorial'
  | 'house'
  | 'tower'
  | 'bridge'
  | 'art'
  | 'combat'
  | 'challenge';

interface BlueprintFile {
  formatVersion: number;
  physicsVersion: number;
  cardSpecVersion: number;
  gameVersion: string;

  metadata: BlueprintMetadata;
  requirements: BlueprintRequirements;
  cards: BlueprintCard[];
  steps: BlueprintStep[];
  challenge?: BlueprintChallenge;
  preview?: BlueprintPreview;
  lineage?: BlueprintLineage;
  verification?: BlueprintVerification;
}

interface BlueprintMetadata {
  id: string;
  name: LocalizedText;
  description: LocalizedText;
  authorId?: string;
  authorName: string;
  category: BlueprintCategory;
  tags: string[];
  difficulty: number;
  createdAt: string;
  updatedAt: string;
  allowRemix: boolean;
}

interface BlueprintRequirements {
  cardSize: CardSize;
  cardCount: number;
  minimumArea: [number, number];
  requiredFeatures: string[];
}

interface BlueprintCard {
  id: string;
  localPosition: [number, number, number];
  localRotation: [number, number, number, number];
  stepId: string;
  recommendedPresetId?: string;
  groundedEdge?: 'long' | 'short' | 'none';
  requiredContacts?: BlueprintContact[];
  positionTolerance: number;
  rotationToleranceDegrees: number;
  optional?: boolean;
  role?: 'support' | 'roof' | 'brace' | 'rail' | 'shield' | 'core' | 'ammo';
}

interface BlueprintStep {
  id: string;
  order: number;
  title: LocalizedText;
  explanation: LocalizedText;
  cardIds: string[];
  freezeDuringBuild: boolean;
  releasePhysicsAfterStep: boolean;
  stableSeconds?: number;
  cameraHint?: BlueprintCameraPose;
  allowSkip?: boolean;
}
```

蓝图旋转建议存四元数，而不是欧拉角。

## 9. 坐标系统

蓝图必须使用局部坐标。

### 9.1 蓝图原点

默认原点：

- X/Z 使用建筑包围盒中心；
- Y 使用建筑最低点；
- 正面方向由作者指定。

### 9.2 导入放置

玩家导入后可以：

- 选择地面放置点；
- 整体绕Y轴旋转；
- 镜像；
- 显示指定层；
- 从指定步骤开始。

不允许任意缩放，因为卡牌尺寸和接触关系不能随缩放变化。

## 13. 稳定性认证

认证由游戏自动生成，作者不能手动伪造。

状态：

- 未测试；
- 成功搭建；
- 静止稳定；
- 通过轻风；
- 通过强风；
- 通过落物；
- 通过实战。

认证记录：

- 使用的物理版本；
- 测试参数；
- 稳定时间；
- 最大位移；
- 倒塌与否；
- 测试日期。

修改蓝图后，旧认证失效，需要重新测试。

---

## 14. 安全和验证

蓝图文件只能包含声明式数据，不能包含脚本。

导入时必须：

- 验证文件格式版本；
- 验证字段类型；
- 限制卡牌数量；
- 限制坐标范围；
- 拒绝`NaN`和无穷值；
- 限制文本长度；
- 清理富文本；
- 禁止文件路径；
- 禁止外部URL；
- 忽略作者上传的伪造认证；
- 重新生成本地ID；
- 不覆盖同名本地作品；
- 对未知字段采用安全忽略或拒绝策略。

未来服务器和创意工坊版本还需要：

- 举报；
- 屏蔽；
- 内容审核；
- 作者封禁；
- 版本撤回；
- 恶意刷榜检测。

## 15. 官方新手教学内容

第一章建议制作四份官方蓝图。

### 教学01：两张牌A字架

学习：

- 接地边；
- 左右倾斜；
- 顶部接触；
- 成组释放物理。

步骤：

1. 放置左侧支撑。
2. 放置右侧支撑。
3. 释放物理。
4. 稳定3秒。

### 教学02：双A字支撑

学习：

- 两组支撑间距；
- 对称性；
- 屋顶承重点。

### 教学03：横梁和屋顶

学习：

- 高度锁定；
- 空槽上方移动；
- 跨度；
- 接触范围。

### 教学04：一层房屋

学习：

- 组合基础结构；
- 控制牌数；

## 18. 测试计划

### 数据测试

- 保存和加载无精度丢失；
- 坐标转换可逆；
- 四元数归一化；
- 格式迁移；
- 非法字段；
- 极端坐标；
- 超大蓝图；
- 重复ID。

### 交互测试

- 移动蓝图原点；
- 整体旋转；
- 镜像；
- 切换步骤；
- 隐藏投影；
- 撤销和重做；
- 切换卡牌尺寸；
- 中途退出后恢复。

### 判定测试

- 位置边界；
- 角度跨越`±180°`；
- 相同姿态不同欧拉表示；
- 倾斜方向相反；
- 长短边接地；
- 多张牌竞争同一目标；
- 可选牌；
- 结构倒塌。

### 兼容性测试

- 旧物理版本；
- 旧卡牌尺寸；
- 中英文文本；
- 不同游戏版本；
- 浏览器开发版；
- Electron桌面版。

## 20. 风险与控制

### 风险一：蓝图判定过于严格

控制：

- 使用容差；
- 显示具体错误；
- 分辅助等级；
- 允许镜像和替代方案。

### 风险二：蓝图变成机械描图

控制：

- 每步解释结构作用；
- 逐步减少辅助；
- 加入记忆挑战；
- 鼓励改造而不是完全复制。

### 风险三：复杂结构无法稳定复现

控制：

- 记录物理版本；
- 分组冻结；
- 稳定认证；
- 作者从空场景测试；
- 允许标记实验性蓝图。

### 风险四：创作工具开发量过大

控制：

- 先完成快照蓝图；
- 再加入步骤编辑；
- 最后加入录制和社区；
- 第一版不建设大型在线后台。

### 风险五：玩家上传恶意文件

控制：

- 纯数据格式；
- 严格验证；
- 数量和范围限制；
- 不执行任何蓝图代码；
- 社区举报和审核。

## 21. 当前推荐实施范围

下一阶段只实施最小闭环：

1. 蓝图数据格式。
2. 将当前建筑保存为蓝图。
3. 自动转换为局部坐标。
4. 本地蓝图库。
5. 加载并投影完整蓝图。
6. 隐藏和删除投影。
7. 导入导出蓝图文件。
8. 数据安全验证。
9. 使用游戏内实际搭建结果创建第一份A字蓝图。

暂不实施：

- 创意工坊；
- 游戏内社区；
- 点赞和评论；
- 在线审核；
- 排位蓝图；
- 自动生成复杂教学步骤；
- 蓝图商业化。

完成最小闭环后，再基于真实使用体验开发步骤编辑器和教学运行器。

## 22. 最终验收目标

蓝图系统完成后，应实现以下完整场景：

1. 开发者或玩家在游戏中搭建一个稳定结构。
2. 点击“保存为蓝图”。
3. 系统生成局部坐标蓝图和预览信息。
4. 作者可以编辑搭建步骤和说明。
5. 另一名玩家导入或订阅蓝图。
6. 玩家选择辅助等级并亲手完成搭建。
7. 游戏判断每一步和最终稳定性。
8. 玩家可以收藏、挑战或基于此蓝图改造。
9. 改造版本保留原作者和来源。
10. 官方教学、玩家作品、社区挑战和对战结构共用同一套蓝图基础。

蓝图系统的最终价值不是替玩家完成建筑，而是让建筑知识可以被保存、学习、传播和继续创造。
